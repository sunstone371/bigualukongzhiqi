# 调试踩坑记录

本项目开发过程中实际遇到并解决（或绕过）的问题，复刻/二次开发前建议通读，能省很多时间。

## 1. ESP8266 空闲 STA 的 WiFi 信道随机漂移（最隐蔽）

**现象**：两块板都 `WiFi.mode(WIFI_STA)` + `wifi_set_channel(1)`，刚开始 ESP-NOW 通信正常，运行一段时间后壁挂炉端 LED 快闪（90 秒收不到遥测）。串口心跳显示信道在 1/5/12/13/14 之间随机跳变，`wifi_set_channel(1)` 重申也拉不回来。

**根因**：ESP8266 的 STA 在**未连接任何 AP** 时，SDK 内部会让射频信道随机漂移，`wifi_set_channel()` 无法长期锁定。两端各自漂移后不在同一信道，ESP-NOW 自然收不到。

**解决**：**壁挂炉端开 SoftAP**（`WiFi.softAP(AP_SSID, AP_PASS, 1)`），**客厅端 STA 连接这个 AP**——连接成功后两端信道跟随 AP 锁定同步，问题彻底消失，且不依赖家里路由器。

**附带发现**：ESP-NOW 工作时 `wifi_get_channel()` 的返回值不可靠（乱跳但通信正常），别用它判断信道状态。

## 2. GPIO15 (D8) 驱动继电器：上电误吸合

**现象**：继电器接 D8，每次上电/复位/自愈重启瞬间锅炉被呼叫。

**根因**：GPIO15 是 boot strap 引脚，板上自带下拉电阻，boot 阶段必为低电平；配低电平触发继电器 = 上电即吸合。

**解决**：换普通 IO（本项目用 GPIO14/D5）。同理避开 GPIO0/D3（按住进刷机模式）。

## 3. 5V 低触发光耦继电器模块 + 3.3V MCU：关不断

**现象**：断开时引脚输出 3.3V，但继电器仍保持吸合。

**根因**：模块输入回路是 `5V → 限流电阻 → 光耦LED → IN`。IN=3.3V 时 LED 两端仍有 5−3.3=1.7V 压差（超过 LED 约 1.2V 导通阈值），微导通电流足以让 PC817+三极管驱动继电器吸合。

**尝试过但无效的软件方案**：`OUTPUT_OPEN_DRAIN` 开漏输出高阻——高阻时模块 5V 上拉与 ESP 引脚 ESD 保护二极管（钳位到 3.3V）形成微电流回路，光耦仍微导通。

**有效方案（硬件，三选一）**：见 [wiring.md](wiring.md) 的电平适配一节（HIGH 触发跳线 / 串 1N4148 二极管 / NPN 三极管反相）。

## 4. 设置界面"按一下就退出"：millis() 时间戳下溢

**现象**：按 SET 进入设置后，一按 UP/DOWN 立即"保存退出"，数值没变。

**根因**：`handleUi()` 内部重新取了 `millis()` 记录操作时间，而 15 秒超时判断用的是 loop 开头的旧时间戳——同一轮循环里 `(now - lastActMs)` 无符号下溢成约 49 天，被误判为超时。旧版固件 loop 快、时间差常为 0ms 所以没暴露，加了日志后 loop 变慢就必现。

**解决**：`handleUi()` 改用 loop 传入的同一时间戳，超时判断改有符号比较 `(int32_t)(now - lastActMs) >= TIMEOUT`。

## 5. OLED 不显示：u8g2 静默失败

**现象**：上传后 OLED 全黑，其它功能正常。

**排查**：u8g2 的 I2C 初始化失败**不报任何错**。给固件加了开机 I2C 总线扫描（扫描全部 127 个地址），串口直接报告结果：
- 扫不到设备 → 接线问题（本项目实际是 SDA/SCL 接反）
- 扫到 0x3C/0x3D → 驱动型号或地址问题（1.3 寸屏常是 SH1106，固件提供 `OLED_SH1106` 宏切换）

**经验**：固件里保留"每 2 秒重试扫描"，接好线不用重新上电即自动点亮。

## 6. I2C 400kHz vs 100kHz

OLED 刷屏在 100kHz 下每帧阻塞主循环约 100ms，按钮采样窗口变大导致快速点按漏检；400kHz（SSD1306 支持）降到约 25ms，按键恢复跟手。

## 7. ESP-NOW 接收回调的上下文安全

ESP8266 的 `esp_now_register_recv_cb` 回调运行在系统上下文：**回调里只做 `memcpy` 到 volatile 缓冲 + 置标志**，校验（长度/魔数/CRC）与业务逻辑全部放 `loop()` 处理，避免竞态。

## 8. 串口掉线自愈经验

- 电脑休眠后 CH340 串口会进入"半死"状态（端口在但打不开，`OSError 22`），重新插拔 USB 恢复；
- 长时间观察设备日志时记得关闭休眠。
